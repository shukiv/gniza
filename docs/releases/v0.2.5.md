# v0.2.5

## Reporting a problem is filling in one form

**Report a problem** now opens the tracker's own new-issue form with the
subject and the description already in it. Type what went wrong, press
**File it**, press GitHub's button. That is the whole of it.

Before this, the page handed over a file and told the operator to go and
find a form, pick a product on it, and attach the file — three steps for
something that should be one, and two of them somewhere else.

Reports go to <https://github.com/shukiv/gniza/issues>. Anyone can open one
and it needs nothing installed, which is the same reason the previous
release stopped shipping an intake key: a plugin published to every cPanel
server cannot hold a credential without publishing it too.

**Download it** is still there and still worth pressing. The link carries
what you typed; the file carries what this server knows — versions, recent
failures, settings without credentials, and the last 200 lines of the
service log, redacted. Attach it to the issue.

A URL cannot hold a whole report. A long description is cut short in the
link and says so where it was cut; nothing is silently lost, because the
file has all of it.

## Unchanged

Nothing is transmitted from the server on its own. The reviewed report is
still signed and still expires after twenty minutes, so what downloads is
what you read.
