# v0.2.5

## Reporting a bug is one form again

**Report a problem** opens this project's issue tracker with what you typed
already in it. Type the subject and what happened, press **File it**, and
GitHub's new-issue form arrives filled in; you press GitHub's own button to
send it.

Before this the page handed over a file and left you to find a form, pick a
product on it, and attach the file — three steps for one action, two of them
somewhere else.

Reports go to <https://github.com/shukiv/gniza/issues>. Anybody can open one
and nothing needs installing, which is the same reason
[v0.2.2](v0.2.2.md) stopped shipping an intake key: a plugin published to
every cPanel server cannot hold a credential without publishing it too.

The intake that was tried first is not usable from here. It replaces the key
with a Cloudflare Turnstile token, and Turnstile only issues one to a page
served from a hostname on its list — while a WHM plugin is served from each
customer's own hostname. There is no arrangement of the plugin that changes
that.

## What goes in the issue

What you typed. **Download it** is still there and still gives you the
diagnostics as a file to attach: versions, this server's recent failures, its
settings without credentials, and the last 200 lines of the service log,
redacted.

[v0.2.6](v0.2.6.md) puts those diagnostics straight into the issue as well,
so filing is one press.

## Filing carries what is in the fields

**File it** is a button that submits the form, not a link. A link's target is
fixed when the page is drawn, which is before anything has been typed — a
link would have opened an empty issue list. What it carries goes through the
same redactor as the preview, so the copy you reviewed is the copy that
reaches a public tracker.

## Unchanged

Nothing is transmitted from the server on its own. The reviewed report is
still signed and still expires after twenty minutes, so what downloads is
what you read.
