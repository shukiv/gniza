# v0.2.9

## Picked files really are sized by what they are

[v0.2.8](v0.2.8.md) said a restore of a few files out of a large account
would ask only for what those files come to. It asked the backup, got the
answer, and then threw it away: the estimate looked at the answer only
for *Restore one thing*, so picking files still reserved the whole
account and was still refused on exactly the accounts it was meant to
unblock. The listing was fetched over the network for nothing.

It is used now. Three files out of a 48.7 GiB account are sized as three
files.

## A mailbox is a folder

The same page called a mailbox a file. It is a maildir — a folder of
messages — so it is sized like any other folder: the backup can say what
a list of files comes to, but not what is under a directory, and a guess
that came out low would fill the volume. A mailbox restore falls back to
the account's own figure.

What genuinely is a file, and so is sized exactly: a database dump, a DNS
zone, a certificate, a cron job, an FTP setting.

## Nothing else changed

The restore-space work in v0.2.8 stands: an apply hands cPanel the
extracted directory rather than a tar of it, a rehearsal builds no
archive and needs one copy of the account, and a listing containing a
folder is treated as an unknown size rather than summed.
