# v0.3.11

## A browser on a server without a panel

A server with no cPanel and no DirectAdmin had the terminal interface
and nothing else. It now has the same pages the panels show, in a
browser, on an address the installer asks about:

    Where should the browser interface listen?
      1) this machine only, 127.0.0.1:8443 -- from your own machine run
         ssh -L 8443:127.0.0.1:8443 root@<this server>  and open http://127.0.0.1:8443/
      2) every address, 0.0.0.0:8443 -- reachable from the internet, over TLS,
         behind the password set next; open port 8443 in the firewall
      3) nowhere -- the terminal interface only (gniza-agent -tui)

The root-only socket's mode was its authorization; a port has none, so
the port brings its own. One password, asked for on the terminal without
echo and kept as a bcrypt hash in `/etc/gniza/web/password`; a session
cookie that ends after twelve hours, an hour idle, or a restart; a wait
after five wrong passwords from one address that doubles with each one
after; and, on every address, TLS with a self-signed certificate made on
first start, whose fingerprint the service logs and `openssl` reads back
from `/etc/gniza/web/cert.pem`. On loopback the port is plain HTTP, for
ssh or a reverse proxy to carry.

The password is changed with `gniza-agent -web-set-password` and applies
to the next sign-in. The answer to the question is kept in
`/etc/gniza/plain.env` as `GNIZA_WEB_LISTEN`, so an upgrade does not ask
again and the unit is unchanged; an unattended install answers with the
same variable, and `GNIZA_WEB_PASSWORD`, set before the script.

A restore and a change of settings, which the terminal does not ask for
yet, can now be asked for from a browser on such a server. ADR 0024 has
the reasoning; the [plain-server guide](../guide/plain-server.md) has
the how.

## Under it

The pages are what they were: behind a panel a fragment the panel's
chrome wraps, and through the browser door the same fragment inside a
document of its own, with a sign-out in the rail. A door that cannot be
opened -- no password set yet, the address in use -- is said in the log
and costs the backups nothing.
