# v0.3.13

## A restore no longer stops at an SELinux label

On a server with SELinux, restic could not put a file's `security.selinux`
label back in the directory a restore is rebuilt in, and one file it could not
label failed the whole restore. On one server that was 24 accounts in 54 —
found by the scheduled rehearsals, which is what they are for.

The label is now left out of a restore. It says what the file was where it was
backed up, not where it is being put; a restored file takes the label of the
directory it lands in, and the panel's own restore labels what it puts into a
home.

## A database with nothing in it does not fail a rehearsal

A database with no table is dumped as a header, a footer and nothing between
them. A rehearsal read that as a dump that would restore nothing, failed the
account and said so to the notification channels. It is a faithful backup of
what the account has.

A dump that creates nothing passes when it says it was finished, and the
rehearsal names the database: *with nothing in it, as on the server*. One that
creates nothing and stops before its end is still refused, as an empty file is.
