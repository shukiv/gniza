# v0.3.15

## A cPanel backup leaves out the one-click installers' archives

Installatron, Softaculous and WP Toolkit write a fresh copy of a site and a
dump of its database under the account's home on every automatic update —
`application_backups`, `softaculous_backups`, `wordpress-backups`. Each copy is
a new compression that shares almost nothing with the night before, so they
were gigabytes of upload every night for what the backup already holds
directly. DirectAdmin servers have left them out since v0.2.x; cPanel servers
obeyed only `cpbackup-exclude.conf`.

They are now left out on cPanel too, under every account's home, without
anybody having to write an exclusion file.

## A killed database restore leaves no login behind

v0.3.14 removed the password file an interrupted database restore left in the
temporary directory, and only named the login that went with it. At the
operator's word, the login is now dropped as well at startup — only a login of
exactly the shape Gniza makes, `cpr_restore_` and sixteen hex digits, so an
operator's own login that happens to share the prefix is left alone.
