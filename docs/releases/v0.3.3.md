## Installing on a server without bunzip2

The one-line installer stopped on a DirectAdmin server with everything
else in place — the release verified, the checksum matched — because
`bunzip2` was not installed:

    error: bunzip2 is needed to install restic; install it and run this again

restic is published as a `.bz2` and nothing else, so something on the
machine has to read one. A minimal AlmaLinux does not have `bunzip2`, and
naming a command leaves an operator to work back to a package on their
own.

`bzip2` is tried next, and then `python3`, whose standard library reads
bz2 and which both panels need for their own reasons. Only when none of
the three is there does the installer stop, and it now names the package
and the command this machine installs it with:

    error: nothing here can read a .bz2, which is the only way restic is
    published: dnf install -y bzip2, or install restic yourself, and run
    this again

Both the WHM and the DirectAdmin installer had it. Both are fixed.
