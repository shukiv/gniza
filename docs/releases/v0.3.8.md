# v0.3.8

## The pages are daisyUI

Every page of the plugin — the WHM and DirectAdmin pages an operator
uses, and the pages a customer sees — is now built with daisyUI on
Tailwind. The look is daisyUI's own: its `light` theme by default, its
`dark` theme from the same switch in the rail, and its buttons, badges,
tables, tabs, alerts, dialogs and form controls throughout. Nothing
about what a page does has changed: every form, link, filter and
dialog is where it was and posts what it posted.

The typefaces stay Fira Sans and Fira Code. The rail is lighter and
sits in a card of its own; a running job's progress is a real progress
bar; a table row's severity is a stripe on its leading edge, as before.

## Under it

The stylesheet is compiled from `internal/webui/ui/input.css` with
`make css` and committed, so a build, a release and a server never need
Node. Every class is namespaced `cpr:` — ADR 0009's rule with Tailwind's
prefix — and two cascade-layer rules keep the host panel's own
stylesheets out of the fragment entirely: measured against WHM's
chrome, no property on any element of ours is set by WHM. ADR 0023 has
the details. The release build fails if the committed stylesheet is
stale.

The terminal interface for a server without a panel is unchanged; its
palette is its own.
